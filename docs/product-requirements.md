# Loading Effects 产品需求

## 使用者与场景

应用开发者需要在不同框架下复用相同的等待体验，设计师需要预览并交付可复现的参数。按钮、表单和局部请求优先使用小尺寸几何动效。列表和详情首屏用与真实内容尺寸一致的骨架。上传或批处理接入任务进度。画布和 AI 生成使用点阵、粒子或生成类动效，允许宿主在收到真实预览后逐步替换占位。

目标是通过统一参数、按需引入和框架适配交付 Web 动效。任务执行、取消、重试、进度采集及内容渲染由宿主负责。动效库消费任务状态，AI 主题可以抽象表达等待，不能据动画推断生成模型的内部阶段。

## 状态与反馈

| 状态 | 可见反馈 | 宿主输入 |
| --- | --- | --- |
| 未知进度 | 循环动画与状态文案，如“正在生成图片” | `progress=null` |
| 确定进度 | 百分比与真实填充 | 任务提供的 `progress=0–100` |
| 估算进度 | 文案和无障碍名称都标注“预计”，缺少可靠估算时进入未知进度 | `progressSource=estimated` 和估算值 |
| 内容就绪 | 暂停动效并过渡到内容，点阵和百分比同步退出 | 宿主明确发出完成信号 |
| 失败或取消 | 停止动效，由宿主展示错误或恢复入口 | 宿主发出终态，忽略该任务随后到达的更新 |

百分比达到 100% 后可显示“正在准备预览”，直到内容就绪。宿主切换任务时应使用任务标识丢弃上一次的迟到消息，组件实例的状态更新不能让旧任务覆盖新任务。进度从未知变成确定时，继续当前动效，无需重建画布。

## Playground 产品验收

当前 Playground 将动效按类别纵向排列，每张卡片保留自己的参数、暂停状态和演示进度。预览离开视口时暂停绘制，重新进入时从原相位继续。进度演示区分未知、确定和预计三种状态。卡片显示实际渲染器，Canvas 不可用时显示静态备用图形。代码区支持复制 Vue、React 和 Web Components 的 JS 或 TS 示例。

后续计划包括按名称或 ID 搜索、浅色和深色背景切换、预设分享链接、显示更具体的降级原因，以及独立的 Vanilla JS 复制模板。

## 里程碑

当前工作区已实现 v0.1 的 14 个预设、CSS 与 Canvas 2D 渲染，以及 Vanilla JS、React 和 Vue 接入。`v0.2.0` 已接入 5 种进度反馈、6 种粒子和 4 种骨架占位，累计 29 项，并提供 Web Components 适配。`v1.0.0-alpha.1` 补齐 4 种文字动效。`v1.0.0-alpha.2` 增加两种 Canvas 2D 流体预设。`v1.0.0-alpha.3` 增加 WebGL 2 渲染器和三种流体预设，累计 38 项。运行入口和演示见[快速开始](index.md)。

| 版本 | 动效范围 | 可交付结果 |
| --- | --- | --- |
| v0.1 | 01–14，共 14 项 | 先做 09 点阵波浪纵向样例，再交付 8 项基础几何和 6 项点阵。CSS、Canvas 2D、Vanilla JS、React 和 Vue 接入，提供可运行的 Playground 初版。 |
| v0.2 | 15–20、30–38，共 15 项，累计 29 项 | 粒子、进度和骨架，交付 Web Components 适配、进度语义和降级测试，扩展 Playground 参数面板。 |
| v1.0 | 21–29、39–50，共 21 项，累计 50 项 | 流体、文字、AI、3D 与品牌效果，交付 WebGL、完整 Playground、文档站和兼容性验证。 |

每期先验收该批动效的视觉、边界参数、暂停与销毁，再检查框架接入、减少动态、按需打包及文档示例。50 项清单及单项参数见[动效目录](effect-catalog.md)。首个画布预设见[点阵波纹规范](dot-matrix-ripple.md)。

画布加载的视觉与交互需求见[点阵波纹 PRD](dot-matrix-ripple-prd.md)。原始分类和图片见[动效库构想](loading-effects-concept.md)。
